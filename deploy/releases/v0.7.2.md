# Edge Manager v0.7.2

Gateway console fixes, and provisioning fixes found by a new OpenWrt test
harness.

## The gateway console no longer garbles

- On the gateway's local console (HDMI / tty1, and the live image), the
  dashboard looked garbled and flickered after a VPN refresh. procd's hotplug
  and init scripts write to the same console on every network reload, and
  those lines stayed on screen.
- The dashboard now rewrites every line in place every 10 s, and every
  second while a console action runs and for 10 s after it. It never clears
  the screen, so it doesn't flash. The old once-a-minute full clear is gone.
- iotgw agent v0.7.2, pinned in the install flow. The live image served by
  the netboot carries the same fix.

## Provisioning (iotgw-kestra)

- **Observability (Alloy):** installs and starts on OpenWrt. The glibc it
  needs is vendored (Debian 12 libc6 + libgcc-s1, provenance recorded) and
  copied from the controller. Before, the stack failed on every run.
- **Mosquitto:** installs the shadow tools needed for its user and group.
- **System:** dockerd is restarted when its configuration changes, so the
  stacks that follow already run on it, without waiting for a reboot.
- **Tests:** `tests/harness/` provisions every Docker stack, Alloy and lldpd,
  twice, on an OpenWrt 23.05 container, with the production runner and role.
  CI runs it on every push.

## Tools

- **HDMI Viewer** (`tools/hdmi-viewer`, Windows): drops the damaged MJPEG
  frames that USB capture cards send (decoded with libjpeg-turbo). Those
  frames looked like a flickering, shifted, blue-tinted picture. See
  task-159.

## Upgrade notes

- No database migrations. Frontend, backend and contract unchanged
  (0.13.1, 1.3.1, 0.3.1). Images rebuilt from the tag.
- Gateways get agent v0.7.2 at their next install.
