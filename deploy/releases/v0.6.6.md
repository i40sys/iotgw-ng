# Edge Manager v0.6.6

Provisioning cleanup and a reusable Uptime Kuma stack.

## Uptime Kuma is its own stack

- New provisioning tag `uptime-kuma` with its own switch and section in the
  deployment form: admin user, admin password and (advanced) port.
- `observability` is now Grafana Alloy and the containers exporter only.
  Alloy scrapes Uptime Kuma when that stack is on, with the Kuma admin login.
- Uptime Kuma monitors only the gateway's own services: its containers, its
  DNS, the MQTT broker port and Alloy. The cloud, factory and internet groups,
  the site devices and their fields are removed.
- The stack no longer needs a prepared database: the admin account is created
  from the deployment on the first start.

## Removed provisioning stacks

- `bugfixing`: its STP setting is part of `system` (the LAN bridge template).
- `glpi-agent` and `plc_sniffer`, including the GLPI firewall rule and LuCI link.
- `credentials` (`/etc/config/credentials` with the GHCR and Notion keys).

Existing gateways keep what these stacks installed; nothing is uninstalled.

## Upgrade notes

- Three database migrations remove the dropped keys from stored deployment
  configurations and set `uptime_kuma: false` where a configuration has none.
- Frontend 0.12.0, backend 1.2.0, contract 0.2.0. Edge functions: unchanged
  code, rebuilt from the tag.
