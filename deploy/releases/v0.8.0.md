# Edge Manager v0.8.0

Node-RED is complete on version 5, gateway hardening, and simpler
configuration actions.

## Node-RED

- **Version 5.0.9** (was 3.1). Gateways that run 3.1 upgrade on the next
  provisioning and keep their flows.
- **Flows repo (optional):** with *Load flows from a Git repo* on, the
  provisioning runner clones `github.com/<org>/flows.<hostname>` and copies
  it to the gateway as the active Node-RED project. For a private repo, an
  optional read-only token stays on the runner. No Git key or credential is
  ever stored on the gateway. Local changes made in the editor that were not
  pushed are kept, with a warning, instead of being overwritten.
- **Settings from the version 3 stack** carried over to version 5: the
  admin login, editor title and options, function modules, and telemetry
  off. Stored flow credentials are now encrypted with a key generated on
  each gateway (it used to be a fixed key).

## Hardening

- **Firewall:** the web-UI allow-list comes only from the deployment's
  *Management networks*. A single site's address that was allowed on every
  gateway is removed.
- **Pinned images:** code-server (VSCode) and the containers exporter run
  fixed versions instead of `latest`.
- **Containers exporter:** its metrics are collected on the configured port.
  Before, they were only collected if the port was 8118.
- **Cleaner logs:** a first installation no longer shows the red, ignored
  `fatal: … is not a directory` for each stack.

## Deployments page

- The Configuration panel's actions (*Save as new version*, *Discard edits*,
  *Delete version*) are buttons next to *Save changes*, instead of a `⋯`
  menu.

## Upgrade notes

- No database migrations. Frontend 0.14.0, backend 1.4.0, contract 0.4.0.
  Edge functions: unchanged code, rebuilt from the tag.
- Provisioning (iotgw-kestra) is covered by 13 tests that provision every
  stack on an OpenWrt container twice. See task-160.
