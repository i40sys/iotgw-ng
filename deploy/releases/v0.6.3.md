# Edge Manager v0.6.3

An OpenWrt install now leaves the gateway enrolled in SSH-CA: the operator
types the one-time code once, at the PXE live boot, and nothing else.

## Install-time SSH-CA enrollment (task-153)

- The install flow enrolls the freshly installed OpenWrt through its own iotgw
  agent, chrooted into the new root filesystem:
  `iotgw ssh refresh -offline`. It writes the same files and `sshd_config.d`
  drop-ins as provisioning and the console's `[s]`, checks them with the
  installed `sshd -t`, restores everything on failure, and never touches a
  running sshd. OpenWrt's `/etc/init.d/sshd` serves the host certificate from
  the first boot.
- The one-time code comes from the backend: `POST /internal/devices/enroll-code`
  accepts `reinstall: true`, which first clears the server's record of the
  previous host key (as "Reset SSH enrollment" does) and writes an audit entry.
  A reinstalled gateway no longer fails with 409 "device already enrolled".
- Provisioning then reaches the new OS with the iotgw-ops certificate and only
  renews.

## SSH-CA survives sysupgrade

- The sysupgrade keep list now includes the SSH-CA files (ecdsa host key and
  certificate, User/Host CA, auth_principals, revoked_keys, known_hosts).
  OpenWrt kept the drop-ins but not the files they point at; a missing
  `RevokedKeys` file makes sshd reject every key login, break-glass included.
  Gateways installed before this release need the line added (re-run the
  install, or append the same paths to `/etc/sysupgrade.conf`).

## Agent

- `iotgw ssh refresh -offline` (agent v0.6.3, pinned by the iotgw-kestra install).
- QEMU OpenWrt e2e: offline enrollment leaves sshd running untouched, `sshd -t`
  and `sshd -T` accept the configuration, `sysupgrade -l` keeps every SSH-CA
  file, and after a power cycle sshd serves the certificate to a strict client.

The backend image changes (enroll-code `reinstall`); frontend and functions do
not.
