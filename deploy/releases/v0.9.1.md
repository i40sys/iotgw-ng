# Edge Manager v0.9.1

Security fix for the Kestra database.

## Security

- **CVE-2026-116328 (CVSS 8.8):** an integer wraparound in PostgreSQL
  generation memory contexts lets a database user run code as the OS user of
  the server. PostgreSQL 16 before 16.16 is affected.
- **Kestra Postgres** went from 16.15 to **16.16**. The image is now pinned to
  the minor version (`postgres:16.16`), not the floating `postgres:16` tag.
  The floating tag is the reason OVH stayed on 16.15.
- **New NetworkPolicy `kestra/kestra-postgres`:** only the Kestra server pod
  can reach port 5432. All other pods are blocked, including the Kestra
  Ansible runner pods.
- The Supabase database (StackGres, PostgreSQL 15.19) is not affected.

## Upgrade notes

- Same major version (16), so no dump and restore. The StatefulSet restarts the
  pod on the existing data volume.
- After the database restarts, restart Kestra
  (`kubectl -n kestra rollout restart deploy/kestra`). Its JDBC queues do not
  recover cleanly from a dropped connection.
- No database migrations. The frontend, backend, contract, edge functions and
  flows are unchanged.
