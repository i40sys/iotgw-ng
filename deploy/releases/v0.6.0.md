# Edge Manager v0.6.0

This release makes the gateway provisioning boot chain a CI/CD product: the
bootable live image and an iPXE chainloader are now built, tested and
published by CI, ready to be served from the OVH netboot. It also closes the
kind → OVH migration.

## Live provisioning image built by CI (task-149.01)

- The bootable image (`vmlinuz`, `initrd`, `filesystem.squashfs`) is built from
  **pinned upstream Clonezilla 3.1.2-9** plus the iotgw overlay — no longer from
  a hand-maintained tree on the old netboot host.
- **No SSH key material** in the image: a CI gate fails the build on any private
  key, `ssh_host_*` key or `authorized_keys` in the rootfs or the initrd. Host
  keys are generated at boot; operators log in as root with an SSH certificate
  only (`PermitRootLogin prohibit-password`, no passwords).
- `wireguard-tools` (pinned) for the VPN step; the initrd carries a static curl
  and CA bundle so live-boot fetches the squashfs over **HTTPS**.
- Every change is boot-tested under QEMU (squashfs fetch, `iotgw-bootstrap`,
  sshd). Tags publish it to `ghcr.io/i40sys/iotgw-live-image` as an OCI artifact
  with build provenance; the release carries `live-image-oci.txt` (`ref@digest`).

## iPXE chainloader (task-149.03)

- New `netboot/chainloader/`: pinned iPXE v2.0.0 with an embedded script that
  chains `https://netboot.iotgw.i40sys.com/menu.ipxe` over HTTPS only, trusting
  just the Let's Encrypt ISRG roots, with a fallback menu when unreachable.
- Release assets: `ipxe.efi` (UEFI), `undionly.kpxe` (BIOS PXE), `ipxe-usb.img`
  (hybrid USB), `chainloader-SHA256SUMS`, build provenance.
- CI runs a QEMU suite on every change: UEFI and BIOS PXE, USB on UEFI and
  BIOS, untrusted-certificate and unreachable-server fallbacks, and a
  reproducibility rebuild.

## Operations since v0.5.0

- OVH runs v0.5.0 with a declared and verified release manifest (task-150).
- kind is development only: production data removed, Kestra gateway schedules
  disabled on every deploy, destructive dev commands refuse any non-kind
  context (task-151). The field gateway gw-c3 now uses the OVH device API
  (task-144).
- The always-failing `connectivity-check` cron schedule was removed; checks
  stay on demand. The Kestra runner may read pod events (task-152).
- The OVH Terraform state bucket is locked down as code: scoped S3 user
  policy, SSE, versioning with noncurrent expiry (task-143).
- Component versions are unchanged: frontend `0.11.0`, backend `1.1.0`.

## Upgrade notes

No application or database change. Serve the image from the OVH netboot by
pinning the digest from `live-image-oci.txt` (task-149.02). Flash
`ipxe-usb.img` or install `ipxe.efi` / `undionly.kpxe` on a site TFTP server to
reach it. The iPXE binaries are unsigned: disable Secure Boot on machines that
boot them.

Changes are relative to `v0.5.0`.
