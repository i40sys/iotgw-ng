Editorial decisions:
- Protocol examples Modbus/OPC UA are possibilities to validate, not a supported
  protocol catalogue. A MQTT-to-MQTT bridge is not an industrial protocol converter.
- Node-RED/MQTT/container foundation is included as selectable services. Machine
  connectors, data maps, transforms and business logic require integration.
- Store and Forward is an application-level delivery function: persist pending data,
  retain it through communication failure, then resume delivery. Local SQL/TSDB
  history is a separate function for queries and local applications after delivery.
  Both require service integration/configuration, capacity and retention choices.
  Keep the existing extensible scope; do not turn persistence alone into a proven
  universal lossless-delivery claim. UDP needs application-level receipt confirmation.
- Owner clarification, 2026-11-04: local apps include bespoke HMI, Grafana machine
  dashboards and local AI agents reacting to process data. The site now leads with
  these functions and benefits, not internal implementation product names.
  Offline operation depends on local data, models and dependencies. Hardware resources
  must match apps/AI. Examples describe project integrations, not turnkey installed apps.
- Owner-supplied connectivity scope includes HTTP, TCP, UDP, MQTT, Kafka, Azure IoT Hub,
  Azure Event Hubs and AWS. Separate protocols/transports from event platforms and cloud
  destinations. Example AWS destinations: IoT Core, Kinesis Data Streams, Data Firehose,
  S3. Each requires its connector, authentication, message mapping and delivery policy.
- Primary references used to confirm cloud service names and roles (2026-11-04):
  https://learn.microsoft.com/en-us/azure/iot-hub/iot-hub-compare-event-hubs
  https://docs.aws.amazon.com/iot/latest/developerguide/kinesis-firehose-rule-action.html
  https://docs.aws.amazon.com/firehose/latest/dev/
  https://docs.aws.amazon.com/whitepapers/latest/building-data-lakes/data-ingestion-methods.html
  These sources document destinations, not a verified NG compatibility matrix.
- Deterministic machine control and machine safety stay with the relevant control and
  safety systems. NG can host local HMI/visualization; the FAQ now states this explicitly.
- The hardware recommendation does not imply arbitrary CPU/driver support; current
  installation targets OpenWrt x86_64.
