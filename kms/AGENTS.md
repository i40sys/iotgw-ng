# Cosmian KMS

Self-hosted Cosmian KMS for SSH key and X.509 PKI management. Full details in [README.md](README.md).

> **LICENSE / ROADMAP**: Cosmian KMS is licensed **BUSL-1.1** (production use is
> limited to ≤ 2 vCPU; it must not be offered as a service to third parties). It is
> an excellent product, but it **will be removed from iotgw-ng soon** and replaced by
> an open-source KMS. See the root [NOTICE](../NOTICE).

## Role in iotgw-ng

This KMS is the authoritative store for device SSH keys. The Supabase `devices` table stores only `ssh_key_id` — the actual key material lives here. Reference architecture in [decision-010](../backlog/decisions/decision-010%20-%20SSH-Key-Management-with-Cosmian-KMS.md).

- **Keys are generated by the iotgw-ui backend** (`iotgw-ui/apps/backend/src/services/kms.ts`, KMIP 2.1 REST): automatically when a device is created, and on demand via `generateMissingSshKey`.
- **The Kestra flows only fetch them** (`fetch_kms_key.py` in `github.com/i40sys/iotgw-kestra`) to deploy them onto the gateway.

> **SECURITY (task-057)**: In the k8s deployment the KMS requires
> **API-token authentication** and is fronted by a **NetworkPolicy** — it does not
> run open. (TLS terminates at the edge; in-cluster KMS traffic is plaintext but
> locked down by the NetworkPolicy.) Details:
>
> - **Auth — Cosmian KMS API token** (`[http] api_token_id` in
>   `deploy/k8s/base/kms/configmap.yaml`). The server fetches the symmetric key
>   `iotgw_api_token`, base64-encodes its raw bytes (lowercased), and requires
>   every request to present it as `Authorization: Bearer <token>`. `/version`
>   and `/health` stay public (so k8s probes work); the KMIP endpoint
>   (`/kmip/2_1`) returns **401** without the token. The token VALUE is a secret:
>   it lives in the SOPS store (`secrets/iotgw-ui-backend.enc.env` →
>   `KMS_AUTH_TOKEN`). `deploy/kind/bootstrap.sh` bridges it into the `kms-auth`
>   k8s Secret in **both** `iotgw-ui` (backend Deployment, `KMS_AUTH_TOKEN` env) and
>   `kestra` (Ansible runner pods, `secretKeyRef`). The key is provisioned
>   idempotently by `deploy/kind/bootstrap.sh kms-auth` (run while the KMS is still
>   open — chicken-and-egg).
> - **NetworkPolicy** (`deploy/k8s/base/kms/networkpolicy.yaml`) default-denies
>   ingress to `:9998` except from its **cross-namespace** clients: the
>   **iotgw-ui-backend** pod (namespace `iotgw-ui`), the **kestra** pod, and
>   **kestra-spawned Ansible runner pods** (`app.kubernetes.io/managed-by: kestra`,
>   namespace `kestra`) — each allow rule combines `namespaceSelector` AND
>   `podSelector` in one `from:` peer (`decision-020`). Clients reach the KMS at
>   the FQDN `cosmian-kms.kms.svc.cluster.local:9998`. The kind cluster's
>   `kindnet` CNI **does enforce** this (verified live); host→NodePort traffic is
>   consequently blocked, so the `/version` smoke falls back to an in-cluster
>   check from the backend pod. Prod NetworkPolicy enforcement depends on the OVH
>   MKS CNI (not verified).

## Stack

- Cosmian KMS **5.27.1** — StatefulSet `cosmian-kms` in namespace `kms`, port 9998, SQLite backend on a PVC, single replica; the manifest pins `ghcr.io/cosmian/kms:5.27.1` (`deploy/k8s/base/kms/statefulset.yaml`; 5.20.0 broke on containerd 2.2)
- Cosmian CLI 1.9.0 at `contrib/cosmian` (see [contrib/README.md](contrib/README.md)). The binary is **gitignored** (`/kms/contrib/cosmian`): download it locally before use.
- Python (uv) for `src/kms_tools/convert_keys.py` (PKCS8 ↔ OpenSSH)
- Pre-commit + commitizen for conventional commits

## Quick commands

```bash
just bootstrap                                         # (repo root) bring the platform (incl. KMS) up on kind
kubectl -n kms rollout status statefulset/cosmian-kms  # KMS up?
./contrib/cosmian kms server-version                   # verify (note: :9998 host path is
                                                       #   blocked by the task-057 NetworkPolicy;
                                                       #   the KMS is reached in-cluster)
uv sync                                                # install Python deps
uv run convert-keys pkcs8-to-ssh in.pem out            # convert exported key
```

## Integration points

- **iotgw-ui backend** generates and reads device SSH keys (`services/kms.ts`).
- **Kestra install/provisioning/connectivity-check flows** fetch keys with `fetch_kms_key.py` (Bearer `KMS_AUTH_TOKEN` from the `kms-auth` Secret).
- **`pki-test/`** holds a test-PKI recipe (`create_ca.sh`, `ca.ext`/`server.ext`/`client.ext`, [README](pki-test/README.md)); generated `*.pem`/`*.p12` are gitignored. Its certs are stored in `secrets/traefik-tls.enc.yaml` and are used **only** by the `deploy/k8s/overlays/prod` sketch. kind uses `secrets/device-api-tls.enc.yaml` (ingress-nginx default cert); OVH uses the Traefik Gateway (`deploy/k8s/overlays/ovh/gateway.yaml`).
